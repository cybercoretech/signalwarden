01 / CURRENT CAPABILITIES

Useful signal.
No mystery traffic.

Phase 1.1 focuses on a small set of details Android already knows, plus an explicit connection check whose destination and behavior are documented.

01 / CONNECTION
⌁

See the active path.

View transport, internet validation, metered status, and Android's VPN transport indicator. The screen refreshes when Android reports network changes.

02 / LINK DETAILS
⌘

Inspect the essentials.

Review interface name, device addresses, DNS servers, proxy configuration, and a short route summary exposed by Android.

03 / ON-DEMAND TEST
◉

Measure each stage.

When tapped, SignalWarden shows Android resolver-call, TCP-connect, and verified TLS times for example.com:443. Resolver timing may include cache; TCP tries at most two DNS answers with bounded timeouts.

04 / SMALL PERMISSION SET
⛨

Keep the boundary clear.

Phase 1.1 requests only Android's Internet and network-state permissions. No account, analytics, telemetry, ads, or app backend.

02 / PRIVACY + SCOPE

Private by design
means specific.

Network diagnostics can expose sensitive details. SignalWarden tells you what it reads and what its test sends.

READ THE PRIVACY NOTES ↗
PHASE 1 / CURRENT SCOPELOCAL ONLY
  • ✓Network snapshot displayed on your device
  • ✓DNS + verified TLS probe only after your tap
  • ✓No stored diagnostic history or remote upload
  • —No VPN service, packet capture, filtering, or background scanning

The DNS resolver and example.com may observe ordinary request metadata when you run the test. Your displayed IPs, routes, and resolver details are not sent to a SignalWarden server.

03 / BUILT IN PHASES

The project is exploring a broader diagnostics and privacy toolkit. Future capabilities remain clearly marked as research until implemented, tested, and reviewed.
